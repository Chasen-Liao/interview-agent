# Interview Agent 0.1.4 交互优化方案与任务清单

## 1. 本版本目标

0.1.4 只优化面试入口交互，不改变 Agent 的产品定位：

- Agent 仍然只做技术面试，不扩展为通用代码助手。
- 模型配置能力保持现状，不在 0.1.4 扩展多账号或模型市场。
- 重点处理面试首屏和输入区交互，让用户更自然地提交 JD、简历和面试回答。

## 2. 用户反馈拆解

| 序号 | 用户期望 | 当前状态 | 0.1.4 处理方式 |
|---|---|---|---|
| 1 | 将发送按钮和停止按钮整合成一个，并放到输入框右下角 | 当前是输入框右侧两个独立按钮 | 改为一个浮动状态按钮：空闲时发送，等待回复时停止 |
| 2 | `简历 / 项目背景` 调整为简历区，增加附件上传，输入区作为简历补充 | 当前把简历和项目背景混在一个 textarea | 拆成“简历区”，支持上传简历附件，并保留文本补充 |
| 3 | 项目情况改为自动读取所在工作区下的项目 | 当前首屏让用户手填项目背景 | 移除项目背景输入，启动面试时由 Agent 自动读取当前 VS Code 工作区 |

## 3. 冲突检查与取舍

### 3.1 两个按钮合一

当前输入区有 `send` 和 `stop` 两个按钮。合并后会带来一个交互变化：

- 空闲状态：按钮图标为发送，点击发送当前输入。
- 等待回复状态：同一个按钮图标变为停止，点击发送 `stop`。

风险：

- 用户需要通过图标状态理解当前按钮行为。
- 当前 Python Agent 的 `stop` 仍是同步 no-op，占位能力有限。

处理建议：

- 0.1.4 先完成 UI 合并和协议发送。
- 不在本版本重构 Python Agent 为异步可取消；真正中断生成作为后续版本单独处理。

### 3.2 简历附件上传

VS Code Webview 不能直接可靠访问本机文件路径，推荐通过 Extension Host 调用文件选择器，然后读取文件内容。

0.1.4 推荐范围：

- 支持 `.txt`、`.md` 简历附件读取。
- 文件内容和“简历补充”一起进入首轮面试上下文。
- 对 `.pdf`、`.docx` 暂不做正文解析，只提示用户先转成文本或粘贴关键内容。

原因：

- 当前项目没有 PDF/DOCX 解析依赖。
- 为附件上传立刻引入解析依赖会扩大打包体积和故障面。
- 简历信息本质是面试上下文，第一版优先保证可用和稳定。

如用户确认需要 PDF/DOCX 正文解析，可在 0.1.4 中扩展为增强任务：

- Node 侧增加轻量解析依赖，或
- Python Agent 侧增加简历解析工具。

### 3.3 项目情况自动读取

当前 Agent 已经通过 `workspace.workspaceFolders?.[0]?.uri.fsPath` 获取目标项目路径，并把它传给 Python 工具层。

0.1.4 的调整不是新增项目读取能力，而是：

- UI 上删除“项目背景”手填区。
- 首轮消息明确告诉 Agent：项目情况从当前工作区自动读取。
- Python 系统提示继续强调用 `list_directory`、`search_code` 摸项目概况。

风险：

- 如果用户没有打开文件夹，Agent 只能 fallback 到插件运行目录。

处理建议：

- Webview 首屏显示当前工作区名称或路径摘要。
- 未打开工作区时，点击开始面试给出错误提示，要求先打开目标项目文件夹。

## 4. 目标 UI

### 4.1 首屏结构

```text
Interview Agent

模型配置区

岗位 JD
[textarea]

简历
[上传简历]  已选择：xxx.md
[textarea: 简历补充，可选]

当前项目
自动读取：当前 VS Code 工作区

[开始面试]

聊天区

[输入框                         ↗]
```

### 4.2 输入区按钮

输入区从当前布局：

```text
[textarea] [发送] [停止]
```

调整为：

```text
┌─────────────────────────────┐
│ 输入内容                    │
│                             │
│                         ↗   │
└─────────────────────────────┘
```

等待回复时：

```text
┌─────────────────────────────┐
│ 输入内容                    │
│                             │
│                         ■   │
└─────────────────────────────┘
```

按钮固定在输入框右下角，避免占用侧边栏横向空间。

9. 补测试：Manifest、防 Tree View 回归、关键 UI 状态逻辑。
10. 编译、测试、打包 `interview-agent-0.1.4.vsix`。

## 7. 0.1.4 验收标准

### 7.1 侧边栏加载

- 安装 `interview-agent-0.1.4.vsix` 后，点击 Activity Bar 的 `Interview Agent`。
- 不显示 `没有可提供视图数据的已注册数据提供程序`。
- 显示完整 Webview UI。

### 7.2 输入区按钮

- 输入区右下角只有一个按钮。
- 空闲状态点击该按钮发送消息。
- 等待回复状态按钮切换为停止。
- `Enter` 仍可发送，`Shift+Enter` 仍可换行。

### 7.3 简历区

- 页面标题为 `简历`，不再是 `简历 / 项目背景`。
- 可以点击上传简历。
- `.txt`、`.md` 简历能读取并显示文件名。
- 简历补充输入区可继续手动补充。
- 点击开始面试后，简历附件内容和补充内容会进入首轮面试上下文。

### 7.4 项目自动读取

- 不再要求用户填写项目情况。
- 页面显示当前工作区项目。
- Agent 开始面试后自动通过工具读取当前工作区项目结构。
- 如果没有打开工作区，开始面试时给出错误提示。

### 7.5 打包产物

- 生成文件：

```text
D:\project\interview-agent\vscode-extension\interview-agent-0.1.4.vsix
```

- 包内 `extension/package.json` 满足：

```text
version = 0.1.4
contributes.views["interview-agent"][0].id = interview.chatView
contributes.views["interview-agent"][0].type = webview
```

## 8. 暂缓事项

以下内容不建议放入 0.1.4：

- PDF / DOCX 简历正文解析。
- 真正异步中断 Python Agent 生成。
- 多简历版本管理。
- 自动生成面试报告。
- 自动创建 Python venv 或自动安装 Python 依赖。
