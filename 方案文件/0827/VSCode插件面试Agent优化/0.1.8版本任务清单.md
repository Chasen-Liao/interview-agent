# Interview Agent 0.1.8 优化方案与任务清单

## 1. 当前版本发布判断

当前 `0.1.7` 可以发布到 GitHub Release，建议定位为 **Pre-release / Beta 试用版**，供他人通过 `.vsix` 手动安装体验；暂不建议标记为稳定正式版，也暂不建议直接发布到 VS Code Marketplace。

判断依据：

| 检查项 | 当前结果 | 发布判断 |
|---|---|---|
| Git 状态 | 当前工作区干净，最新提交为 `6f76595 优化面试面板页面布局` | 通过 |
| Python 测试 | `196 passed` | 通过 |
| Python lint | `ruff check agent` 通过 | 通过 |
| VS Code 扩展测试 | `64 passed` | 通过 |
| TypeScript 类型检查 | `npx tsc -p ./ --noEmit` 通过 | 通过 |
| VSIX 打包 | 已生成 `vscode-extension/interview-agent-0.1.7.vsix` | 通过 |
| 侧边栏入口 | Activity Bar Webview View 已注册并测试覆盖 | 通过 |
| 面试核心闭环 | JD / 简历 / 当前项目 / 对话 / 历史会话 / 真实 LLM 已具备 | 可试用 |

需要在 Release Notes 中明确的限制：

1. 真实模型调用依赖用户自己的 OpenAI 兼容 API Key、Base URL 和模型名。
2. 如果模型名与服务商不匹配，会出现模型不存在类错误；0.1.8 应提供模型连接测试按钮降低配置成本。
3. Python 依赖通过 VS Code Terminal 明示安装，不做静默安装。
4. OCR 依赖相对偏重，当前只作为扫描版 PDF 简历 fallback。
5. README 与扩展内 README 需要在 0.1.8 更新，当前发布时应通过 GitHub Release Notes 补足使用说明。
6. 当前 VSIX 包含较多 `node_modules` 文件，`vsce package` 有 bundle 优化警告；不阻塞 GitHub 预发布，但后续应优化体积和启动性能。

结论：

- **可以发布**：GitHub Release `v0.1.7`，勾选 `Set as a pre-release`。
- **不建议发布为稳定版**：等 0.1.8 完成模型连接测试、README 更新、报告导出后再考虑稳定发布。

## 3. 0.1.8 本版本目标

0.1.8 的目标是把 `0.1.7 Beta` 从“可试用”推进到“更适合公开给他人安装使用”。

本版本包含 5 个目标：

1. **会话标题自动生成增强**：已有基础标题生成规则，本版本增强标题质量和刷新时机。
2. **面试报告导出**：将会话内容生成结构化 Markdown 报告。
3. **模型连接测试按钮**：在设置中一键验证 API Key、Base URL、模型名是否可用。
4. **OCR 轻量化选型确认**：调研并确定是否继续使用 RapidOCR，或改为可选 OCR 后端。
5. **README 文档更新**：补齐安装、配置、使用、发布、隐私和故障排查说明。

产品边界不变：插件只做技术面试，不扩展为通用代码助手。

## 4. 当前状态与任务取舍

4. 不做多模型账号管理，只做当前配置的连接测试。

## 5. OCR 开源项目调研结论

候选项目：

| 项目 | GitHub | 优点 | 风险 | 建议 |
|---|---|---|---|---|
| RapidOCR | [RapidOCR](https://github.com/rapidai/rapidocr) | 开源、支持多平台、多语言，默认中英文，安装方式简单；当前项目已使用 `rapidocr-onnxruntime` | OCR 包和模型仍会增加安装时间 | **优先继续使用**，0.1.8 做可选安装和失败降级 |
| OCRmyPDF | [OCRmyPDF](https://github.com/ocrmypdf/OCRmyPDF) | 专门处理扫描 PDF，可生成可搜索 PDF，成熟度高 | 依赖 Tesseract 和系统安装，对普通 VS Code 插件用户门槛更高 | 不作为默认内置；可作为后续高级 OCR 方案 |
| Tesseract | [Tesseract](https://github.com/tesseract-ocr/tesseract) | 老牌 OCR 引擎，支持 100+ 语言和多种输出格式 | 需要系统级安装，Windows 用户配置成本较高 | 不作为默认方案 |
| EasyOCR | [EasyOCR](https://github.com/JaidedAI/EasyOCR) | 支持 80+ 语言，API 简单 | 依赖 PyTorch，体积和安装成本偏高 | 不适合当前“轻便”目标 |
| PaddleOCR | [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | 功能强、生态成熟，支持 PDF/图片到结构化数据 | 功能过大，依赖更重 | 后续如做复杂文档理解再评估 |

0.1.8 推荐方案：

- 保持 RapidOCR 路线。
- 将 OCR 依赖从“主依赖”改为“可选依赖/按需安装提示”。
- 普通 PDF、DOCX、TXT、MD 不触发 OCR。
- 扫描版 PDF 才提示安装 OCR 依赖。
- OCR 失败时保持可粘贴文本兜底。

依据来源：

- [RapidOCR](https://github.com/rapidai/rapidocr)：项目说明其支持多平台、多语言和离线部署，默认支持中英文，并提供 `pip install rapidocr onnxruntime` 使用方式。
- [OCRmyPDF](https://github.com/ocrmypdf/OCRmyPDF)：项目说明可给扫描 PDF 添加 OCR 文本层，支持旋转、纠偏、多核处理，并依赖 Tesseract。
- [Tesseract](https://github.com/tesseract-ocr/tesseract)：项目说明支持 100+ 语言、PNG/JPEG/TIFF 和多种输出格式。
- [EasyOCR](https://github.com/JaidedAI/EasyOCR)：项目说明支持 80+ 语言，Windows 上需要先安装 torch/torchvision。
- [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)：项目说明支持 PDF/图片到结构化数据，支持 100+ 语言。

## 8. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| LLM 标题/报告生成增加费用 | 用户无感消耗 token | 标题和报告生成要可失败回退；报告导出由用户主动触发 |
| 连接测试误写入会话 | 污染历史记录 | 连接测试走独立路径，不进入 `.sessions` |
| OCR 依赖拆分导致旧用户缺包 | 扫描 PDF 识别失败 | 缺 OCR 依赖时提供明确安装按钮和文本粘贴兜底 |
| README 与实现再次不一致 | 发布后用户困惑 | 增加文档关键字段静态测试 |
| 报告包含隐私信息 | JD、简历、对话泄露风险 | 默认保存本地工作区，导出前提示，README 写明隐私边界 |

## 9. 0.1.8 验收步骤与验收标准

验收步骤：

1. 在 `vscode-extension` 下执行：

   ```powershell
   npm test
   npx tsc -p ./ --noEmit
   npm run compile
   npm run package
   ```

2. 在项目根目录执行：

   ```powershell
   .\.venv\Scripts\python.exe -m pytest
   .\.venv\Scripts\python.exe -m ruff check agent
   ```


9. 点击导出报告，确认 Markdown 报告生成并可打开。
10. 上传普通 PDF 和扫描版 PDF，确认 OCR 路径只在扫描 PDF 时触发。
11. 阅读 README，按 README 步骤重新完成一次 Demo Mode 使用流程。

验收标准：

- 所有自动测试、类型检查、lint、编译和打包通过。
- 模型连接测试能在不开始面试的情况下给出成功/失败结果。
- 错误模型名提示明确，不再只暴露长堆栈。
- 历史会话标题可读，不依赖用户理解 session id。
- 面试报告成功导出为 Markdown，内容包含薄弱点和复习建议。
- OCR 依赖未安装时不影响普通简历上传和面试。
- README 能指导新用户完成安装、配置和基础使用。

## 10. 本版本改进建议

1. **先补发布可用性**：模型连接测试和 README 更新优先级高于新增复杂能力。
2. **报告先做 Markdown**：避免 PDF 样式、字体、跨平台渲染带来额外复杂度。
3. **OCR 保持可选**：当前项目只需要读取简历文字，不需要完整文档结构化解析。
