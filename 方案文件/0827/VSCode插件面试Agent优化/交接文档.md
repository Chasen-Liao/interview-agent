# Interview Agent VS Code 插件优化交接文档

## 1. 项目与目标

项目路径：

```text
D:\project\interview-agent
```

本轮对话围绕 `Interview Agent` VS Code 插件优化展开。目标是把原本偏开发调试的面试 Agent，改造成可安装到任意目标项目中的 VS Code 插件，并在侧边栏中进行面试交互。

产品边界已经明确：

- 插件只做技术面试 Agent。
- 模型切换是运行配置，不扩展为通用 Agent 平台。
- Agent 可以读取当前工作区项目用于面试追问，但不做自动写代码、改代码、提交代码。

## 2. 关键需求

本轮主要需求包括：

1. 打包为正式可安装 VS Code 插件。
2. 在 Activity Bar / Side Bar 中提供面试入口。
3. 支持在插件中切换模型配置。
4. 修复侧边栏显示 `没有可提供视图数据的已注册数据提供程序` 的问题。
5. 将发送和停止按钮合并为输入框右下角单一状态按钮。
6. 将 `简历 / 项目背景` 改为 `简历` 区。
7. 增加简历附件上传区域。
8. 项目情况改为自动读取当前 VS Code 工作区。
9. 新增项目级 `AGENTS.md` 开发验收规则。

## 4. 重要修复记录

### 4.1 VS Code 侧边栏 Provider 错误

用户验收时发现侧边栏出现：

```text
没有可提供视图数据的已注册数据提供程序
```

最终根因：

```json
"type": "webview"
```

最初没有声明在 `contributes.views["interview-agent"]` 的 `interview.chatView` 上，导致 VS Code 将该视图按普通 Tree View 处理，从而查找 TreeDataProvider。

修复方式：

- 在 [package.json](../../../vscode-extension/package.json) 中为 `interview.chatView` 增加 `"type": "webview"`。
- 新增 [manifest.test.ts](../../../vscode-extension/test/manifest.test.ts)，防止回归。

### 4.2 插件正式安装后找不到 Python Agent

原问题：

- 开发调试时通过插件目录往上找仓库根目录中的 `agent/main.py`。
- 打包安装后，插件目录中没有外层 `agent/`。

修复方式：

- 新增 [prepare-agent.js](../../../vscode-extension/scripts/prepare-agent.js)。
- 打包前复制：

```text
agent/ -> vscode-extension/bundled-agent/agent/
```

- 插件运行时优先从：

```text
context.extensionUri/bundled-agent/agent/main.py
```

启动 Python Agent。

### 4.3 简历上传区域不明显

用户指出：

```text
简历区没有提供上传附件的区域
```

原因：

- 之前只是一个小的 `上传简历` 按钮，不像明确的附件上传区域。

修复方式：

- 版本升到 `0.1.5`。
- 在 [index.html](../../../vscode-extension/src/webview/index.html) 中改为整块 `resume-upload` 上传区域。
- 上传区域包含：
  - `＋` 图标
  - `上传简历附件`
  - `支持 .txt / .md / .markdown`
- [styles.css](../../../vscode-extension/src/webview/styles.css) 增加虚线边框上传区域样式。
- [webview-template.test.ts](../../../vscode-extension/test/webview-template.test.ts) 增加模板断言。

## 8. 当前验收步骤

1. 卸载 VS Code 中旧版 `Interview Agent`。
2. 关闭所有 VS Code 窗口。
3. 重新打开 VS Code，并打开一个目标项目文件夹。
4. 从 VSIX 安装：

```text
D:\project\interview-agent\vscode-extension\interview-agent-0.1.5.vsix
```

5. 执行 `Developer: Reload Window`。
6. 点击左侧 Activity Bar 的 `Interview Agent`。
7. 勾选 `Demo Mode`。
8. 填写岗位 JD。
9. 点击 `简历` 下方的附件上传区域，选择 `.txt`、`.md` 或 `.markdown` 简历。
10. 在简历补充输入区补充一句说明。
11. 点击 `开始面试`。
12. 在底部输入区输入一条回答，观察右下角按钮状态。

## 9. 当前验收标准

### 9.1 侧边栏加载

- 不显示 `没有可提供视图数据的已注册数据提供程序`。
- 面板显示完整 Webview UI。
- 扩展版本为 `0.1.5`。

### 9.2 简历区

- 页面显示 `简历`，不再显示 `简历 / 项目背景`。
- 简历区下方有明显附件上传区域。
- 上传区域包含 `＋`、`上传简历附件`、`支持 .txt / .md / .markdown`。
- 点击上传区域可以打开 VS Code 文件选择器。
- 选择支持格式后，上传区域显示文件名。

### 9.3 项目自动读取

- 页面显示 `当前项目`。
- 当前项目来自 VS Code 当前打开的工作区。
- 未打开工作区时，点击开始面试会提示先打开目标项目文件夹。

### 9.4 输入区按钮

- 底部输入框右下角只有一个按钮。
- 空闲状态显示发送。
- 等待回复状态切换为停止。
- `Enter` 发送，`Shift+Enter` 换行。

### 9.5 Demo Mode

- 勾选 Demo Mode 后，不需要 API Key。
- 可以点击开始面试。
- 聊天区出现用户提交内容。
- 面试官能够回复。

## 10. 后续注意事项

1. 用户后续如果继续反馈 UI 问题，优先检查 `src/webview/*`，改完后必须 `npm run compile`，否则 `media/*` 不会同步。
2. 用户验收 VSIX 时必须安装最新版本，旧版本会被 VS Code 缓存干扰。
3. `.vsix` 文件被 `.gitignore` 忽略，本地可用但不会进入提交。
4. `bundled-agent/` 是打包生成物，也被忽略；打包时由 `prepare-agent.js` 重新生成。
5. 当前只支持 `.txt`、`.md`、`.markdown` 简历正文读取；PDF/DOCX 解析仍是暂缓事项。
6. 当前 `stop` 仍是 UI 和协议层状态切换，Python Agent 真正异步中断尚未实现。
7. 本项目已新增 `AGENTS.md`，之后基于任务清单开发完成后必须测试，并在最终回复给出验收步骤及验收标准。
