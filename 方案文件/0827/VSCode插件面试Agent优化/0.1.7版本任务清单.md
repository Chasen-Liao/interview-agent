# Interview Agent 0.1.7 优化方案与任务清单

## 1. 本版本目标

0.1.7 先解决影响实际使用的产品问题，不做 `asyncio` 全异步化重构。

本版本包含 4 个目标：

1. **真实 LLM 调用与连续交互修复**：非 Demo Mode 下必须调用用户配置的真实模型，连续追问不能重置会话。
2. **依赖自动安装**：缺少 Python Agent 运行依赖时，在面板提供显式安装入口。
3. **历史会话管理 UI**：把已有 `.sessions` 会话落盘能力暴露到侧边栏，支持查看、继续、新建、删除。
4. **扫描版 PDF OCR**：普通 PDF 文字层解析失败时，尝试 OCR 提取简历文字。

产品边界不变：插件只做技术面试 Agent，不扩展为通用代码助手。

## 2. 暂不做 asyncio 的记录

`asyncio` 全异步化本版本不实施。原因：

- 当前已有线程化取消能力，能覆盖“停止生成”的核心体验。
- 0.1.7 同时包含真实 LLM、依赖安装、历史 UI、OCR，已经跨 TS / Webview / Python 多层，继续混入 asyncio 会放大回归风险。
- 用户当前更需要可用的真实面试闭环，而不是底层并发模型重构。

后续处理规则：

- `asyncio` 记录为后续版本候选优化。
- 当后续某个业务确实需要“并发会话、非阻塞多命令处理、更强取消语义、长任务后台调度”时，再把 `asyncio` 列入该版本任务清单。
- 在列入前必须先补充停止、流式输出、工具调用、历史恢复的回归测试。

## 3. 当前问题判断

| 序号 | 优化项 | 当前状态 | 0.1.7 处理方式 |
|---|---|---|---|
| 1 | 面试官像固定回答 | Demo Mode 本来就是固定脚本；同时前端每次发送都会保存配置并重启 Agent，导致上下文丢失 | 真实模式明确标识；普通发送不再重启 Agent；只在配置变化时重启 |
| 2 | 依赖需要手动处理 | 0.1.6 只提示缺 `openai`，没有安装入口 | 缺依赖时显示安装按钮，用 VS Code Terminal 执行 pip 安装 |
| 3 | 历史会话不可见 | Python 已落盘 `.sessions/*.json`，但 UI 无法查看和继续 | Extension Host 直接读取工作区 `.sessions`，Webview 展示历史列表 |
| 4 | 扫描版 PDF 不能上传 | `pdf-parse` 只能读取文字层 | PDF 文本为空时调用 Python OCR fallback |

## 6. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 真实 LLM 依赖外部 API | 手工验收可能受网络、余额影响 | 自动测试用 FakeLLM / mock，真实 API 作为人工验收项 |
| pip 安装可能失败 | 用户机器网络或镜像源不同 | 安装在 Terminal 明示执行，失败可直接看日志 |
| OCR 依赖较重 | 安装慢、识别慢 | 只在扫描 PDF fallback 时触发 OCR，普通 PDF 不走 OCR |
| 历史会话包含简历/代码片段 | 隐私风险 | 存在本地工作区 `.sessions`，提供删除入口，保持 gitignore |

## 7. 0.1.7 验收步骤与验收标准

验收步骤：

1. 在 `vscode-extension` 下安装产物：

   ```powershell
   code --install-extension .\interview-agent-0.1.7.vsix --force
   ```

2. 执行 `Developer: Reload Window`。
3. 打开目标项目文件夹，进入 `Interview Agent` 活动栏面板。
4. 关闭 Demo Mode，填写真实 API Key、模型名和 baseUrl。
5. 填写岗位 JD，上传简历，点击“开始面试”。
6. 连续回答 2-3 轮，观察面试官是否结合上一轮回答继续追问。
7. 点击历史会话入口，确认当前会话出现在列表中。
8. 点击“新建”，再切回旧会话继续发送一条消息。
9. 上传扫描版 PDF 简历，确认出现 OCR 识别状态。
10. 切换到缺少依赖的 Python 环境，确认出现“安装 Agent 依赖”入口。

验收标准：

- 真实模式不会显示 Demo 固定脚本文案。
- 普通聊天不会重启会话，上下文能连续。
- 缺依赖时可通过按钮打开 Terminal 安装。
- 历史会话可刷新、继续、新建、删除。
- 扫描版 PDF 可 OCR；失败时提示清晰且不影响继续面试。
- `npm test`、`npx tsc -p ./ --noEmit`、`npm run compile`、Python pytest、ruff、VSIX 打包全部通过。

## 8. 本版本改进建议

1. **先保核心闭环**：真实 LLM 连续交互是 0.1.7 第一优先级，其他能力不能破坏它。
2. **依赖安装保持透明**：所有安装命令都通过 Terminal 明示执行，不做静默安装。
3. **OCR 只做简历场景**：不扩展成通用图片识别，避免偏离面试 Agent 定位。

## 9. 下一个版本的优化建议

1. **面试报告导出**：生成薄弱点、技术点评价、复习建议的 Markdown 报告。
2. **会话标题自动生成**：根据 JD、项目名和首轮技术栈生成历史标题。
3. **模型连接测试按钮**：单独验证 API Key、baseUrl、model 是否可用。
4. **OCR 可选安装优化**：如果 OCR 依赖过重，将 OCR 拆为可选安装项。

## 10. 后续可扩展的优化建议

1. **asyncio 全异步化**：当后续版本需要并发会话、长任务后台调度或更强取消语义时再纳入任务清单。
2. **题库与项目技术栈匹配**：根据 JD 和项目读取结果自动规划面试大纲。
3. **回答质量评分**：每轮回答后内部打分，最终汇总能力地图。
4. **隐私控制面板**：一键清理简历缓存、历史会话和工具读取记录。
