# Interview Agent 0.1.10 版本开发任务清单

调研日期：2026-08-30

## 1. 本版本目标

0.1.10 聚焦三个方向：OCR 进度可见、VSIX 体积收敛、Agent 框架迁移设计。代码实施时只做前两项和框架评估准备，不直接把现有 Agent 循环整体替换成第三方框架。

目标：

1. 上传扫描版 PDF 或图片简历时，前端能看到 OCR 当前阶段、页数、耗时和可取消状态。
2. 找出 VSIX 体积膨胀来源，删除或排除不需要随包发布的文件。
3. 明确当前自行构造的 Agent 循环与 LangChain、AutoGen、AgentScope 的迁移边界。
4. 给出当前阶段是否适合迁移主流框架的判断，并形成可验证 PoC 清单。

暂不做：

1. 不在 0.1.10 直接引入 LangChain、AutoGen 或 AgentScope 到正式运行依赖。
2. 不把 OCR 模型或 OCR Python 依赖打进基础 VSIX。
3. 不重写现有工具协议、会话落盘、历史压缩和 VS Code Webview 通信。
4. 不为了体积优化牺牲 DOCX、PDF、TXT、MD、图片简历的现有解析能力。

## 2. 当前状态与冲突检查

| 方向 | 当前状态 | 主要问题 | 0.1.10 处理策略 |
|---|---|---|---|
| OCR 反馈 | [resume_ocr.py](../../../agent/resume_ocr.py) 一次性输出最终文本；[webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) 只显示粗粒度状态 | 多页 PDF 识别时用户不知道进度，长耗时像卡住 | 增加结构化进度事件，展示页数、阶段、耗时 |
| VSIX 体积 | 0.1.9 VSIX 约 6.1 MB；运行依赖包含 `pdf-parse` / `mammoth` 及其生产依赖 | `pdf-parse` 自带多份 `pdf.js` 版本，包内文件较多；历史 `.vsix` 虽不在当前 `vsce ls` 输出中，但仍应显式排除 | 先用 `vsce ls` 和压缩包明细定位，再最小化 `.vscodeignore` / 依赖 |
| Agent 循环 | [agent_loop.py](../../../agent/agent_loop.py) 自行实现 OpenAI tool calling 循环 | 可观测性、标准化编排、框架生态不足 | 先抽象 `AgentRuntime` 边界，做离线 PoC，不切主流程 |
| 框架迁移 | LangChain、AutoGen、AgentScope 都能做 agent / tool / 多智能体 | 引入任一框架都会增加依赖、打包体积和迁移风险，与本版本 VSIX 瘦身目标冲突 | 当前阶段不适合正式迁移，只适合评估 |

当前阶段判断：

1. **不适合在 0.1.10 直接迁移框架**。项目仍处在 VS Code 插件交付、上传、OCR、模型配置和基础面试体验打磨阶段，现有单 Agent 循环代码量不大，整体替换收益不足。
2. **适合做架构准备**。把当前循环背后的模型调用、工具注册、历史管理、通知回调梳理成接口边界，后续可以替换 runtime，而不是重写 VS Code 插件和协议层。
3. **适合做 PoC，不适合进正式包**。PoC 放在开发文档或实验目录，比较能力、依赖体积、冷启动、流式输出、工具调用兼容性，不进入发布 VSIX。

## 3. 主流框架调研结论

参考资料：

1. LangChain 官方文档：[LangChain Python Agents](https://docs.langchain.com/oss/python/langchain/overview)
2. AutoGen 官方文档：[Microsoft AutoGen Stable Docs](https://microsoft.github.io/autogen/stable/)
3. AgentScope 中文文档：[AgentScope 文档](https://doc.agentscope.io/zh_CN/)

| 框架 | 适合点 | 对当前项目的成本 | 0.1.10 结论 |
|---|---|---|---|
| LangChain / LangGraph | 单 Agent 工具调用、middleware、后续复杂工作流 | 需要适配当前 OpenAI 兼容模型配置、工具 schema、流式输出、历史压缩 | 作为首选 PoC，对标当前 `AgentLoop.run()` |
| AutoGen | 多 Agent、事件驱动、团队协作、GraphFlow | 当前项目不是多 Agent 产品，迁移会引入异步和事件模型复杂度 | 暂不迁移；只记录为未来多角色面试官方向 |
| AgentScope | 多智能体、工作流、模型/工具/记忆、Tracing 和 Studio | 当前插件侧本地交付更重视体积和稳定；框架依赖与运行模型需实测 | 暂不迁移；可做中文生态和可视化调试 PoC |

推荐路线：

1. 0.1.10：保留现有 Agent 循环，新增框架评估文档和 runtime 边界设计。
2. 0.1.11 或之后：如工具调用复杂度继续上升，优先用 LangChain/LangGraph 做同等能力 PoC。
3. 等到需要多面试官协作、候选人评分仲裁、异步任务队列时，再评估 AutoGen 或 AgentScope。

## 4. 开发任务清单

### 4.1 任务一：OCR 进度事件协议

| 任务 | 说明 | 相关文件 |
|---|---|---|
| 定义进度事件 | 约定 `stage`、`currentPage`、`totalPages`、`elapsedMs`、`message` 字段 | [protocol.py](../../../agent/protocol.py)、[protocol.ts](../../../vscode-extension/src/protocol.ts) |
| OCR 脚本输出进度 | `resume_ocr.py` 在 stderr 输出 JSON Lines 进度，stdout 只保留最终 OCR 文本 | [resume_ocr.py](../../../agent/resume_ocr.py) |
| Host 侧解析进度 | `runResumeOcr` 读取 stderr，JSON 进度转发到 Webview；普通错误仍走原错误提示 | [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) |
| 兼容旧错误 | 非 JSON stderr 继续作为错误文本处理，避免 traceback 被吞 | [webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) |
| 单页图片进度 | 图片识别显示 `准备 OCR`、`识别图片`、`整理文本` 三个阶段 | [resume_ocr.py](../../../agent/resume_ocr.py) |
| 多页 PDF 进度 | PDF 识别显示总页数和当前页，最多仍按前 5 页处理 | [resume_ocr.py](../../../agent/resume_ocr.py) |

验收标准：

1. 扫描版 PDF OCR 时能看到 `第 1/3 页` 这类页数进度。
2. 图片 OCR 时能看到阶段变化和已耗时。
3. stdout 不混入进度 JSON，CLI 直接调用仍只输出识别文本。
4. OCR 失败时仍显示可读错误，不出现空白状态。

| 任务 | 说明 | 相关文件 |
|---|---|---|

| 失败状态明确 | 缺依赖、超时、空结果、格式不支持分别保留现有错误入口 | [main.js](../../../vscode-extension/src/webview/main.js)、[webviewPanel.ts](../../../vscode-extension/src/webviewPanel.ts) |

## 6. 验收步骤与验收标准

### 6.1 自动化验收

在项目根目录执行：

```powershell
cd D:\project\interview-agent
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check agent
$env:INTERVIEW_AGENT_RUN_OCR='1'; .\.venv\Scripts\python.exe -m pytest agent\tests -m ocr -s
```

在 VS Code 扩展目录执行：

```powershell
cd D:\project\interview-agent\vscode-extension
npm test
npx tsc -p ./ --noEmit
npm run compile
npx vsce ls
npm run package
```

自动化验收标准：

1. 所有测试、类型检查、编译和打包命令通过。
2. OCR 集成测试输出图片和扫描版 PDF 的耗时。
3. `npx vsce ls` 不包含历史 `.vsix`、测试数据、source map、无关示例。
4. `interview-agent-0.1.10.vsix` 体积小于 0.1.9，目标小于 3 MB；达不到时必须给出不可删文件来源。

### 6.2 手工验收

1. 安装 0.1.10 VSIX：

   ```powershell
   code --install-extension D:\project\interview-agent\vscode-extension\interview-agent-0.1.10.vsix --force
   ```

2. 执行 `Developer: Reload Window`。
3. 打开任意项目，进入 `Interview Agent`。
4. 上传清晰图片简历，确认显示 OCR 阶段和耗时，完成后简历进入上下文。
5. 上传 2-3 页扫描版 PDF，确认显示当前页数和总页数。
6. 上传普通文字层 PDF，确认不显示 OCR 页数进度。
7. 上传 DOCX / TXT / MD，确认原解析流程不受影响。
8. 查看 `Interview Agent` Output Channel，确认有 OCR start/progress/success/failed 日志。

手工验收标准：

1. OCR 进度不遮挡对话，不造成布局跳动。
2. OCR 成功、失败、取消或再次上传后的状态都能正确收敛。
3. 扫描版 PDF 和图片识别结果仍能命中 0.1.9 的关键字段标准。
4. 瘦身后的 VSIX 安装后功能完整。

## 7. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| stderr 同时承载进度和错误 | 错误提示被 JSON 解析逻辑吞掉 | JSON Lines 加固定字段；非 JSON 保留为错误文本 |
| 进度过于频繁 | Webview 消息刷屏或卡顿 | 只按阶段和页更新，不做毫秒级刷新 |
| 排除依赖文件过多 | PDF / DOCX 解析运行时报缺文件 | 每次 `.vscodeignore` 调整后安装 VSIX 手工验收 |
| 框架迁移引入依赖膨胀 | 抵消 VSIX 瘦身收益 | 0.1.10 不引入正式框架依赖 |
| 框架 PoC 结论不稳定 | 后续迁移方向错误 | 使用同一输入、同一工具、同一模型配置对比 |

## 8. 本版本改进建议

1. OCR 进度优先做“可见且稳定”，不做复杂进度条估算。
2. VSIX 瘦身先处理确定无用的包内容，再考虑替换 PDF 解析库。
3. 框架迁移先做评估文档和 PoC 标准，不在当前版本把主链路变复杂。

## 9. 下一个版本的优化建议

1. 如果 0.1.10 框架评估显示 LangChain/LangGraph 收益明确，0.1.11 做一个不进正式包的 LangChain runtime PoC。
2. 继续修复系统文件资源管理器拖拽上传，补真实 VS Code Webview 手工验收记录。
3. 增加更细的会话可观测性，例如每轮模型耗时、工具耗时、token 粗估和错误分类。

## 10. 后续可扩展的优化建议

1. 当面试流程需要多角色协作时，再评估 AutoGen 或 AgentScope 做多面试官、评分员、总结员。
2. 将 Agent 运行时设计成可插拔 runtime：`native`、`langchain`、`autogen`、`agentscope` 作为实验配置，而不是硬切。
3. 建立端到端 UI 自动化验收，覆盖 VSIX 安装、上传、OCR、对话和报告导出。
4. 如果 VSIX 体积仍偏大，评估把 PDF / DOCX 解析下沉到 Python runtime，减少 Node 生产依赖。
